## ONBOARDING FRICTION AUDIT — 2026-05-28

I walked through the complete signup → first plan flow on mealzy.org. Scoring each step 1-5 (1 = very confusing, 5 = perfectly clear):

```
Step 1: Landing page CTA → Sign up form    [4]
  Clear "Get Started Free" button. CTA visible above fold.
  Minor: could benefit from showing "No credit card required" next to CTA.

Step 2: Sign up form fields                [4]
  Email, name, password — standard and clear.
  Minor: no password requirements shown until you fail validation.

Step 3: Profile setup (goal/diet/budget)   [3]
  Goal selection is clear. Diet options cover main restrictions.
  Issue: "Budget" field has no context — is this daily? Weekly? Per meal?
  Issue: Calorie field has no helper text for users who don't know their target.

Step 4: Dashboard first load               [3]
  Shows empty state but the path forward isn't obvious.
  Issue: No "Generate your first plan" prompt or guided nudge.
  User might not know where to click next.

Step 5: Generate first plan button         [4]
  Button is visible once you find the planner page.
  Minor: button text "Generate Plan" is clear but could be more inviting ("Create My Meal Plan").

Step 6: Plan display — is it clear?        [4]
  Meals are laid out by day/meal time. Easy to read.
  Calories and macros visible. Good.

Step 7: Swap meal — is it discoverable?    [2]
  Critical issue: no visible "swap" button or hover affordance.
  Users don't know they can swap individual meals.
  Tested on mobile — even less discoverable.

Step 8: Grocery list — is it findable?     [3]
  Exists but buried. Users expect it on the plan page or as a tab.
  Currently requires navigating to a separate page.
  
Step 9: Free limit hit — modal clarity     [4]
  Modal explains you've hit 3/3 plans. Upgrade CTA is clear.
  Minor: could show what Pro unlocks right in the modal.

Step 10: Upgrade page — is it persuasive?  [3]
  Lists features but doesn't emphasize the value.
  Issue: No social proof, no testimonials, no "X users upgraded this month."
  Price is clear. Family tier explanation is adequate.

Average score: 3.4/5
Lowest scoring step: Step 7 (Swap meal) — scored 2/5
```

## RECOMMENDED FIXES (flagged to team)

### 🔴 Critical — Step 7: Meal Swap Not Discoverable
**Flag to: Maya (copy) + Morgan (UI)**

Users don't know they can swap meals. This is a key feature that reduces frustration when the AI gives them something they don't want.

**Recommended fix:**
- Add visible "Swap" icon/button on each meal card
- On first plan view, show a tooltip: "Don't like a meal? Click to swap it."
- Mobile: add a "Swap" text link below each meal

---

### 🟡 Major — Step 3: Profile Setup Confusion
**Flag to: Maya (copy) + Drew (product)**

Two fields causing confusion:

1. **Budget field** — no context given
   - Fix: Add helper text "(weekly grocery budget in $)"
   - Or show example: "$50-100/week is typical"

2. **Calorie field** — users who don't know their target skip or guess wrong
   - Fix: Add "Not sure? We'll calculate based on your goal" checkbox
   - Or: link to a quick calculator, or pre-fill based on goal/height/weight/age

---

### 🟡 Major — Step 4: Dashboard Empty State
**Flag to: Maya (copy) + Morgan (UI)**

New users land on dashboard with no clear next action.

**Recommended fix:**
- Add a prominent card: "Ready to eat better? → Create Your First Meal Plan"
- Or: auto-redirect new users to the planner on first login

---

### 🟢 Minor — Step 8: Grocery List Buried
**Flag to: Drew (product)**

Users expect grocery list to be a tab on the plan page, not a separate page.

**Recommended fix:**
- Add "View Grocery List" button directly below the meal plan
- Or: make it a tab on the plan view (Plan | Grocery List | Export)

---

### 🟢 Minor — Step 10: Upgrade Page Needs Social Proof
**Flag to: Casey (pricing) + Maya (copy)**

Page lists features but doesn't persuade.

**Recommended fix:**
- Add: "Join [X] users who upgraded to Pro"
- Add: 1-2 short testimonials or tweets from happy users
- Emphasize the ROI: "$8/mo = less than one takeout meal"

---

### 🟢 Minor — Step 2: Password Requirements
**Flag to: Morgan (UI)**

Password requirements only shown after failed validation.

**Recommended fix:**
- Show requirements below field: "At least 8 characters"
