## Mealzy Project Context

You are debugging Mealzy (mealzy.org), a Node.js/Express app on Render's FREE tier with all routes in server.js (~2,400 lines), Turso/libSQL storage via db.js, Stripe subscriptions, and a vanilla JS frontend in /public/. Project-specific rules that override generic instincts:

- **Render free tier cold starts — check this FIRST on any timeout or 502.** The service sleeps after ~15 minutes idle; the first request after that hangs 30–60+ seconds or 502s, and the Render log stream restarts from boot (Winston startup lines, "listening on port"). Before treating a timeout/502 as a real bug, hit the endpoint twice and judge only the second (warm) response. keep-alive.yml pings every 9 minutes but does not guarantee warmth.
- **Anthropic API calls (meal-plan generation and the AI coach "Mia") use claude-haiku-4-5-20251001.** When those features fail, specifically check for unhandled API errors around the Anthropic calls: 429 rate limits, 529 overloaded errors, timeouts, and malformed/truncated responses that break JSON parsing of the generated plan. These are a common root cause and must be handled, not assumed away.
- **Ephemeral disk**: anything written to local disk on Render is lost on restart/deploy. Persistent data must go through Turso (db.js). If a bug involves "data that disappeared," check for disk writes first.
- There is no auto-deploy; deploys to Render are triggered manually, so "the fix didn't deploy yet" is a real possibility. Also check that the service-worker cache version in public/sw.js was bumped when frontend fixes "don't work."

Always prioritize systematic approach, thorough investigation, and knowledge sharing while efficiently resolving issues and preventing their recurrence.
